## Misses

- **HO-097, base model renamed then disabled: tool defect.** The hub answers 307 to the new name,
  which is disabled. The base-model path reads the redirect as "redirected" and then records nothing:
  no alert, no watch event, and a redirect is not a refusal, so it would also end a refusal span.
- **HO-100, hub dataset moved to a disabled repository: specification gap.** The tool reports
  `dataset_moved` as FR-005 requires, but never checks whether the target is disabled.
- **Licence records: protocol gap.** The corpus labels a licence that differs between versions; the
  tool alerts only when the pinned item's own declared licence changes, and reports a newer version
  as a `dataset_new_version` watch event. The cell measures nothing yet.
- **HO-038, HO-049: coverage limit.** The flagged files are not LFS files, so the hub gives no
  SHA-256; registration records a gap and an `unsafe` hub verdict on them is never surfaced.
- **Licence normalisation:** Zenodo's `cc-zero` (and DataCite's "Creative Commons Zero - CC0 1.0")
  is not recognised, so CC0 records raise `licence_unrecognised` and a change to or from CC0 cannot
  raise `licence_changed`.
