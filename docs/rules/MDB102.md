# MDB102: The hub's own scan calls a pinned hub weight file unsafe

Alert kind `hub_scan`, family weight files.

Related watch kinds: `hub_scan_unknown`

## What raises it

The hub's own security scan names a pinned hub weight file as unsafe, and the file's hash at the scanned revision matches the pinned SHA-256. Severity HIGH by policy.

## What it does not prove

It reports the hub's verdict, not a scan by this tool: no globals are read from hub files, so exceptions and the strict globals policy do not apply to them. A verdict the hub does not give is a `hub_scan_unknown` watch event, not a clean result.

## How it closes

It is cleared when the hub's scan of the same file no longer calls it unsafe, and fixed when a new version no longer pins the file.

## How to fix or accept it

Pin a revision whose file the hub scan accepts, or move to a code-free format. If you accept the risk, dismiss it with a reason. A dismissal holds: a later check that finds the same cause with no new evidence opens no new alert and lists the dismissed alert under the model's `dismissals_held`. New evidence (a changed record, another matched identifier, a higher severity) opens a new alert whose cause names the dismissed one under `reopens`.
