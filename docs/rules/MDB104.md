# MDB104: Pickle globals neither on the safe list nor excepted, under the strict globals policy

Alert kind `globals_policy`, family weight files.

Related watch kinds: none

## What raises it

The model's globals policy is `strict` (`policy ID --globals strict --by NAME`) and the latest static scan of a local pickle weight file reports at least one global, whatever the scanner's label, that is neither on the safe list (`src/model_dependabot/safe_globals/`) nor excepted for the file's SHA-256, or the scan did not complete. One alert per file, severity MODERATE by policy, naming every such global under `unlisted`, the safe list's version and hash and who set the policy and when.

## What it does not prove

It does not say a listed global is harmful: only that the owner has not accepted it. A dangerous global is listed here and also keeps its MDB101 alert. Hub weight files are not judged, because no source reads their globals.

## How it closes

It is cleared at the next check that asks a weight source when the policy returns to `default` (note `cleared: policy`), or when nothing is left unlisted because the safe list or exceptions now cover the rest (note `cleared: safe_list` or `cleared: exception`). It is fixed when a new version no longer pins the file.

## How to fix or accept it

Record an exception for each global you have reviewed in this exact file; one exception also covers the global in the file's MDB101 alert. A global whose module or name contains `unknown` stays listed for good; dismiss the alert with a reason if you accept it. A dismissal holds: a later check that finds the same cause with no new evidence opens no new alert and lists the dismissed alert under the model's `dismissals_held`. New evidence (a changed record, another matched identifier, a higher severity) opens a new alert whose cause names the dismissed one under `reopens`.
