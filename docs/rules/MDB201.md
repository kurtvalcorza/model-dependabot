# MDB201: A pinned package version is affected by a published advisory

Alert kind `package_advisory`, family packages.

Related watch kinds: `advisory_unmatched`, `advisory_gone`

## What raises it

A pinned package version is affected by an advisory, and the advisory source's match agrees with a local evaluation of the same record. Several records that alias one another raise one alert with every id and the highest severity.

## What it does not prove

It does not prove the vulnerable code is reachable from the model. A match the local evaluation cannot confirm is an `advisory_unmatched` watch event; a record that has gone from the source is an `advisory_gone` watch event and the alert stays open.

## How it closes

It is fixed when a new version pins an unaffected package version, withdrawn when the source withdraws the advisory and cleared when the record no longer affects the pinned version.

## How to fix or accept it

Upgrade to a fixed version and register the new inventory. If the code is not used at runtime, dismiss the alert with that reason. A dismissal holds: a later check that finds the same cause with no new evidence opens no new alert and lists the dismissed alert under the model's `dismissals_held`. New evidence (a changed record, another matched identifier, a higher severity) opens a new alert whose cause names the dismissed one under `reopens`.
