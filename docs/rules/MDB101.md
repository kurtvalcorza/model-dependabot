# MDB101: A local pickle weight file imports a dangerous global

Alert kind `weight_file_scan`, family weight files.

Related watch kinds: `scan_suspicious`, `scan_incomplete`, `hash_mismatch`, `weight_file_absent`

## What raises it

A static scan of a local pickle weight file (`picklescan`, in a check or recorded at registration) reports at least one global the scanner calls dangerous, such as `os.system` or `__builtin__.getattr`. The scan reads the file's opcodes; the file is never loaded. Severity HIGH, set by this tool's policy. The cause lists the dangerous globals, the suspicious ones, whether the scan completed and the file's SHA-256.

## What it does not prove

It does not prove the file is malicious: a dangerous global is one that can run code when the file is loaded, and many legitimate checkpoints import one. It does not prove that the file is safe when absent either: a scan that could not finish is a `scan_incomplete` watch event, and an import the scanner could not resolve is reported as `unknown`.

## How it closes

It is fixed when a new version of the model no longer pins the file. It shows as `excepted`, still the same alert, while every dangerous global in its cause is covered by an active exception for the file's SHA-256; a revoked or expired exception returns it to open at the next check that asks a weight source.

## How to fix or accept it

Replace the file with a code-free format (safetensors, ONNX) and register the new version. If you have reviewed the global in this exact file, record an exception: `exception record --global MODULE.NAME --sha256 HEX --reason TEXT --by NAME`. One exception covers the global in this alert and in the file's MDB104 alert. A global whose module or name contains `unknown` can never be excepted; dismiss the alert with a reason instead. A dismissal holds: a later check that finds the same cause with no new evidence opens no new alert and lists the dismissed alert under the model's `dismissals_held`. New evidence (a changed record, another matched identifier, a higher severity) opens a new alert whose cause names the dismissed one under `reopens`.
